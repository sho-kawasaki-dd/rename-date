# Phase 9: プリセットJSON取込時の同名競合対応 実装計画書（v0.4.2）

対象: [rename-date開発計画書.md](./rename-date開発計画書.md) のプリセットJSON取込仕様、テスト方針、配布手順。[Phase 6](./phase6-プリセットJSON保存・取込-実装計画書.md) で追加したJSON入出力、[Phase 8](./phase8-高DPI対応-実装計画書.md) のバージョン管理と配布手順を引き継ぐ。

## 目的

入力パターンと年月・単日・期間の出力テンプレートをJSONから取り込む際、既存一覧に同名の項目がある場合の選択肢を利用者に提示する。重複項目をスキップして他の項目を取り込むか、既存項目を上書きするかを選べるようにし、キャンセルも可能にする。本改修を含むアプリとインストーラーのバージョンを `v0.4.2` に上げ、Windows用インストーラーのビルド・更新インストールまで検証する。

## 要件

### A. 同名競合時の選択

- 入力パターン、年月出力テンプレート、単日出力テンプレート、期間出力テンプレートの4種類すべてに適用する。
- 既存一覧とJSON内の名前が完全一致（大文字小文字を区別）した項目を競合とする。別種類間の同名は競合にしない。
- 競合判定の前に、①内部設定4ファイルパスの拒否、②外部JSON全件の形式・JSON内重複・種別別検証、③内部設定ファイルの厳密読込を完了する。これらに失敗した場合は選択画面を出さず、内部設定（既定値復元を含む）・一覧・プレビューを変更しない。
- JSONファイル内の重複名は従来どおり不正データとして全件拒否する。利用者の選択でJSON内の重複を解決する動作は設けない。
- 競合がある場合に限り、「上書き」「スキップ」「キャンセル」を明確に選べる専用モーダルダイアログを表示する。競合がない場合は確認画面を出さずに通常どおり取り込む。
- 競合選択ダイアログは親ウィンドウに紐づけ、競合する名前を入力JSON内の出現順で表示する。大量競合や高DPI（150%〜200%）・最小ウィンドウサイズ（`700x450`）でもボタンが切れないようスクロール可能な一覧等で表示し、ウィンドウを閉じる操作（`×` ボタン・`Esc` キー）はキャンセル扱い、初期フォーカスは誤上書き防止のため「キャンセル」とする。
- **上書き**では、既存項目の内容をJSON内の同名項目で置き換え、既存一覧中の位置を保つ。競合しない項目はJSON内の順序で末尾に追加する。内容が既存と同一の同名項目であっても「上書き」を選んだ場合は上書き件数に計上する。
- **スキップ**では、既存項目を変更せず、競合しない項目だけをJSON内の順序で末尾に追加する。
- **キャンセル**では、内部設定、一覧、選択状態、プレビュー、再スキャン条件を変更しない。
- 選択後に結合した一覧全体を検証し、追加または上書きが1件以上ある場合に限り、内部設定ファイルを原子的に一度だけ更新する。途中失敗で内部設定を部分更新しない。
- 追加0件かつ上書き0件（＝全件スキップ）の場合のみ「変更なし」として扱い、内部設定への書込みを行わず、一覧・選択状態・プレビュー・再スキャン条件を維持する。
- 完了通知は変更有無に応じて出し分ける。追加または上書きが1件以上ある場合は、追加・上書き・スキップ件数を区別して表示し、再プレビューを案内する。全件スキップにより変更がない場合は、変更がなかった旨とスキップ件数を通知し、再プレビュー案内は出さない。

### B. 既存動作との整合

- 取込元JSONは読み取り専用とし、文字コード・スキーマ・内部設定ファイルへの直接入出力拒否・既存の検証を維持する。
- 実行中は取込を開始しない。追加または上書きが発生した場合は既存の選択維持ルールを適用し、古いプレビューと実行候補を破棄して再プレビューを案内する。Undo履歴は保持する。
- JSON保存時の外部ファイル上書き確認、アプリの変換処理、テンプレート編集画面での同名保存・上書き動作は変更しない。
- `pyproject.toml`、`uv.lock`、Inno Setup単独実行時の既定値を `0.4.2` に揃える。`pyproject.toml` をバージョンの正本とし、既存ビルドスクリプトのバージョン注入とインストーラーの `AppId` は維持する。
- 最終成果物として `installer\Output\rename-date-0.4.2-setup.exe` を生成し、v0.4.1からの更新インストールを検証する。

## タスク

### 1. Services：取込競合の解決

- [ ] [preset_io.py](../src/rename_date/services/preset_io.py) に、競合方針（例: `ConflictPolicy`）、検証済みの既存一覧・取込一覧・競合名一覧（入力JSON出現順）を保持する取込計画型、および更新後一覧・追加／上書き／スキップ件数・変更有無を返す取込結果型を定義する。
- [ ] [pattern_service.py](../src/rename_date/services/pattern_service.py) と [output_template_service.py](../src/rename_date/services/output_template_service.py) の共通取込処理を拡張し、「事前検証・競合抽出（準備）」と「競合方針の適用・原子的保存」の2段階を1回の外部JSON読込で完結できるようにする（ダイアログ表示後に外部JSONを再読込しない）。既存 `import_from_json(path)` の互換方針（既定の拒否動作を維持するか新メソッドを併用するか）を明確にし、4種類すべてで同じ名前比較・順序維持・原子的保存規則を適用する。
- [ ] 事前検証では、内部設定4ファイルパス拒否、外部JSON全件の形式・JSON内重複・種別別検証、および内部設定ファイルの厳密読込（`_load_strict`）を競合判定前に完了する。既存一覧の同名項目は上書き時にその位置で置換（同内容でも上書き件数に計上）し、スキップ時はそのまま残す。非競合項目は入力JSONの順序で追加する。
- [ ] 追加0件かつ上書き0件（全件スキップ）の場合は不要なファイル保存を行わず、変更なしとして呼び出し元へ返す。追加または上書きが1件以上ある場合は結合後一覧を全体検証してから原子的に1回保存する。
- [ ] Services層に `tkinter` を導入せず、既存の厳密な読込・検証・原子的書込み・`tmp_path` を使った実I/Oテストの方針を維持する。

### 2. Views・Controller：競合選択と状態更新

- [ ] [main_window.py](../src/rename_date/views/main_window.py) から呼び出す専用モーダルダイアログ（`tk.Toplevel`、`transient` + `grab_set` + `wait_window`）を追加し、「上書き」「スキップ」「キャンセル」の3選択肢を明示する。競合する名前を入力JSON出現順でスクロール可能な一覧等に表示し、`WM_DELETE_WINDOW` と `Esc` はキャンセル扱い、初期フォーカスは「キャンセル」として高DPI・大量競合でもボタンが切れないレイアウトにする。
- [ ] [app_controller.py](../src/rename_date/controllers/app_controller.py) で、事前検証・競合抽出の完了後に競合がある場合のみ選択ダイアログを表示し、選択された方針をServices層の適用処理へ渡す。競合がない場合は選択画面を出さずに取り込む。キャンセル時や選択前のエラー時には一覧・選択状態・プレビュー・再スキャン条件・内部設定を変更しない。
- [ ] 追加または上書きが1件以上あった場合のみ対象一覧を更新し、既存選択の維持（上書きされた選択中項目の内容・ラベル反映を含む）、プレビュー破棄、実行候補と再スキャン条件の無効化、再プレビュー案内を行う。全件スキップにより変更なしの場合はこれらの状態を維持する。
- [ ] 完了通知の書式を整理し、変更あり時は追加・上書き・スキップ件数と再プレビュー案内を、全件スキップ時は変更なしとスキップ件数（再プレビュー案内なし）を誤解なく表示する。

### 3. 自動テスト

- [ ] JSON内の重複名、不正な項目、検証失敗、内部設定ファイルの欠損・破損、内部設定4ファイルパス指定、ファイル読込・保存失敗では、競合解決へ進まず内部設定を変更・既定値復元しないことを検証する。大文字小文字だけが異なる名前は従来どおり別名として扱うことを確認する。
