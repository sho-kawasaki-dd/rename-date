# **ファイル名一括変換 GUI アプリ (Rename Date) 開発計画書**

## **1\. アプリケーション概要**

### **1.1 目的**

指定されたフォルダ配下を再帰的に走査、またはドラッグ&ドロップされた個別ファイルを対象に、正規表現パターン（年月・単日・期間）にマッチするファイル名を指定の日付表現へ一括変更する GUI アプリケーションを開発する。置換対象パターンは複数選択可能な「パターンプリセット」として、置換後表現は種別ごとの「出力テンプレートプリセット」として、それぞれ JSON に永続化し、GUI 上で選択・追加・編集・削除できる。

### **1.2 主な特徴**

- **再帰的検索**: サブフォルダ内のファイルも対象（隠しフォルダ・VCS 管理フォルダ等は除外）。
- **安心の事前プレビュー**: 変更を実行する前に一覧で差分と処理状態を確認可能。
- **安全設計**: 変更後ファイル名の衝突自動回避（`_1` 連番）、不正日付の実行対象外化、ログ出力。
- **Undo 機能**: 誤って実行した直前のリネーム操作を一括で取り消す（元に戻す）。
- **可変正規表現 & 出力テンプレート**: 年月は2、単日は3、期間は4〜6キャプチャグループのパターンを「パターンプリセット」として複数選択する。期間→単日→年月の順に適用し、同種内の相対順はリスト表示順を保つ（パイプライン方式）。年月・単日・期間の出力テンプレートはそれぞれプリセットとして選択し、JSONで永続化する。
- **プリセットの持ち運び**: 入力パターン・年月/単日/期間出力テンプレートを種類ごとにJSONへ保存し、別環境のJSONから取り込める。
- **ドラッグ&ドロップ**: 対象フォルダをドロップして再帰走査、または個別ファイルをドロップして直接リネーム対象に追加できる。
- **UI 応答性**: 走査・実行・Undo はワーカースレッドで行い、進捗表示とキャンセルに対応。
- **多重起動抑止**: 同時に 2 つ以上のインスタンスが起動しないよう制御。
- **インストーラ配布**: PyInstaller で実行ファイル化し、Inno Setup でインストーラを生成。

### **1.3 主要な決定事項サマリ**

| 項目             | 決定内容                                                                                     |
| ---------------- | -------------------------------------------------------------------------------------------- |
| 置換の契約       | 2グループは年月、3グループは単日、4〜6グループは期間。期間は開始日・終了日の省略形式を正規表現側で吸収する |
| 出力の契約       | 年月テンプレートは `{Y}-{M}`、単日テンプレートは `{Y}{M}{D}`、期間テンプレートは `{Y}{M}{D}-{Y2}{M2}{D2}` を既定とする |
| パターン管理     | 置換対象パターンは「パターンプリセット」として複数選択可能。GUI で選択・追加・編集・削除可能 |
| パターンの適用順序 | 期間→単日→年月の順で適用し、同種内の相対順はリスト表示順を保つ（安定ソート）。置換結果に次のパターンを適用する |
| 出力テンプレート管理 | 年月・単日・期間用を別プリセットで選択・追加・編集・削除する |
| パターン保存先   | `%APPDATA%\rename-date\config\patterns.json`（UTF-8）。初回起動時は既定パターンプリセット1件を生成 |
| 出力テンプレート保存先 | `%APPDATA%\rename-date\config\output_templates.json`（UTF-8）。初回起動時は既定テンプレートプリセット1件を生成 |
| 期間用テンプレート保存先 | `%APPDATA%\rename-date\config\range_output_templates.json`（UTF-8）。既定テンプレートプリセットは `{Y}{M}{D}-{Y2}{M2}{D2}` |
| 年月用テンプレート保存先 | `%APPDATA%\rename-date\config\month_output_templates.json`（UTF-8）。既定テンプレートプリセットは `{Y}-{M}` |
| 括弧の扱い       | 除去する（`Report (2024.1.5) final.pdf` → `Report 20240105 final.pdf`）                      |
| 複数マッチ       | 1 ファイル名中のすべてのマッチを置換する                                                     |
| 拡張子           | 置換対象外。`Path.stem` のみを対象とする                                                     |
| 不正な日付       | `datetime.date` で検証し、`(2024.13.45)` 等はプレビューに「無効」表示のうえ実行対象外        |
| 名前の衝突       | 自動回避。`_1`, `_2` … の連番サフィックスを付与する                                          |
| 走査対象         | ファイルのみ（フォルダ名は変更しない）                                                       |
| 除外             | 隠しファイル・隠しフォルダ、既定の除外ディレクトリ、シンボリックリンクは辿らない             |
| 対象の指定方法   | フォルダ選択（再帰走査）に加え、フォルダ／ファイルのドラッグ&ドロップに対応。ドロップされたファイルは直接リネーム対象に追加（走査を経ない） |
| プレビュー       | 表示専用。個別チェックによる取捨選択は行わず全件一括実行                                     |
| Undo             | メモリ上の複数段 LIFO スタック。アプリ終了で履歴は破棄                                       |
| Python           | 3.12 以上                                                                                    |
| GUI              | 標準ライブラリの tkinter / ttk ＋ `tkinterdnd2`（フォルダ/ファイルのドラッグ&ドロップ用途のみ追加依存） |
| ログ             | `%APPDATA%\rename-date\logs\rename_log.txt`（UTF-8 / サイズベースローテーション 最大 6 MiB） |
| 多重起動         | 抑止する（既存ウィンドウを前面化して新しいプロセスは終了）                                   |
| 配布             | PyInstaller（onedir・ウィンドウアプリ）→ Inno Setup インストーラ                             |

## **2\. 開発環境 & パッケージ管理 (uv)**

本プロジェクトでは Python のパッケージ・環境管理ツールとして **uv** を利用します。

### **2.1 前提条件**

| 項目             | 内容                                                              |
| ---------------- | ----------------------------------------------------------------- |
| Python           | 3.12 以上                                                          |
| パッケージ管理   | uv                                                                 |
| GUI ツールキット | 標準ライブラリ tkinter / ttk ＋ `tkinterdnd2`（ドラッグ&ドロップ用） |
| 開発用依存       | pytest, pytest-cov, pyinstaller                                    |
| 対象 OS          | Windows 10 / 11                                                    |
| レイアウト       | src レイアウト（`src/rename_date/`）                               |

### **2.2 環境構築手順**

```powershell
# 既存リポジトリ直下でプロジェクトを初期化（src レイアウト）
uv init --app --package .

# 開発用依存の追加
uv add tkinterdnd2
uv add --dev pytest pytest-cov pyinstaller

# アプリの起動
uv run main.py

# テストの実行
uv run pytest --cov=src/rename_date
```

初期化後、`pyproject.toml` に以下を設定します。

- `requires-python = ">=3.12"`
- `[tool.pytest.ini_options]` の `pythonpath = ["src"]`

## **4\. 機能要件詳細**

### **4.1 画面機能 (Views)**

1. **設定エリア (ConfigFrame)**
   - 対象の選択: `filedialog.askdirectory` に加え、フォルダ・ファイルの**ドラッグ&ドロップ**にも対応（`tkinterdnd2` 利用）。フォルダがドロップされた場合は従来どおり再帰走査、ファイルがドロップされた場合はそのファイル自体を直接リネーム対象に追加する（複数フォルダ・ファイルの同時ドロップも可、重複は正規化して除去）
   - 正規表現パターンは複数選択可能な一覧から選択する。各行には `[年月]`、`[単日]` または `[期間]` を表示する。期間→単日→年月の順に適用し、同種内は一覧の表示順を保つ。
   - 年月・単日・期間用出力テンプレートを別々の `ttk.Combobox` で選択する。既定はそれぞれ `{Y}-{M}`、`{Y}{M}{D}`、`{Y}{M}{D}-{Y2}{M2}{D2}`。
   - パターン・各種テンプレートそれぞれに「保存/上書き」「削除」「新規」ボタンを配置し、各サービス経由でJSONへ即時永続化する。
   - メニューバーに「プリセット」を追加し、「入力パターン」「年月/単日/期間出力テンプレート」ごとに「JSONに保存...」「JSONから取込...」を配置する。保存はその種類の全件を対象とし、取込は既存一覧への追加とする。
   - 「プレビュー更新」ボタン
2. **プレビューエリア (PreviewFrame)**
   - `ttk.Treeview` による一覧表示。列は **状態 / 変更前ファイル名 / 変更後ファイル名 / 相対パス（複数フォルダ・ファイル混在時はフルパス表示）**
   - 変更対象外ファイル（パターンに一致しない、または置換結果が元と同一）は非表示
   - 状態に応じた行の書式: 不正な日付はグレー表示、連番付与による衝突回避は強調表示
   - 表示専用。個別のチェックによる取捨選択は行わない
3. **操作エリア (ActionFrame)**
   - 対象件数表示（実行対象 / 無効の内訳を併記）
   - 「一括変換を実行」ボタン
   - 「直前の実行を取り消す (Undo)」ボタン（履歴がある場合のみ有効化）
   - ログ保存設定チェックボックス
   - 進捗バーとステータスラベル、処理中の「キャンセル」ボタン

### **4.2 サービスロジック要件 (Services)**

#### **A. 対象収集・置換ロジック (ScannerService)**

**パターンの検証**

- `scan()` は複数のパターン（`patterns: list[str]`、1件以上）と年月・単日・期間の出力テンプレートを受け取る。
- 各パターンについて `re.compile()` に失敗した場合、およびキャプチャグループ数が2〜6以外の場合は `InvalidPatternError` を送出し、走査を行わずに GUI 側でエラーダイアログを表示する。
- 2グループは年月（Y/M）、3グループは単日（Y/M/D）、4グループは期間（Y/M/D/D2）、5グループは期間（Y/M/D/M2/D2）、6グループは期間（Y/M/D/Y2/M2/D2）。
- 年月テンプレートは `{Y}` `{M}`、単日テンプレートは `{Y}` `{M}` `{D}`、期間テンプレートは `{Y}` `{M}` `{D}` `{Y2}` `{M2}` `{D2}` をそれぞれ各1回以上含む。Windows のファイル名不可文字は使用できず、年月テンプレートには対応しないプレースホルダー・不正な波括弧・制御文字を含めない。

**対象収集**

- フォルダを指定した場合: `os.walk(root, topdown=True, followlinks=False)` を使用し、`dirnames` をその場で書き換えて除外フォルダの探索自体を打ち切る。
- ファイルが直接ドロップされた場合: 走査せずそのまま対象に追加する（下記の除外ルールは適用）。
- フォルダ・ファイルが混在してドロップされた場合は、それぞれ上記ルールで収集して合算し、`Path.resolve()` により重複を除去する。
- 除外対象:
  - 隠しフォルダ・隠しファイル（名前が `.` で始まる、または Windows の `FILE_ATTRIBUTE_HIDDEN` が立っているもの）
  - 既定の除外ディレクトリ: `.git`, `.svn`, `.hg`, `node_modules`, `__pycache__`, `.venv`, `venv`, `.idea`, `.vscode`
  - シンボリックリンク / ジャンクション（辿らない）
- 走査対象は**ファイルのみ**。フォルダ名は変更しない。
- 結果の再現性のため、ファイル名はソートして決定的な順序で処理する。
- `threading.Event` によるキャンセル要求を走査ループ内で定期的に確認する。

**置換**

- 置換対象は `Path.stem` のみ（拡張子は保持する）。
- **複数パターンの適用**: 期間→単日→年月の順に適用し、同種内はリスト表示順を保つ（安定ソート）。置換結果（working stem）に後続パターンを逐次適用する（パイプライン方式）。
- 各パターンについて、ファイル名中の**すべてのマッチ**を置換する（`re.sub`）。
- 単日マッチは `datetime.date(Y, M, D)`で検証する。期間マッチは `date_span.parse_match()`で開始日・補完後の終了日を作り、繰り上げ判定は `date()`生成前の数値比較で行う。
- 不正な一致が1つでもあればファイル全体を `INVALID_DATE` とし、以降のパターンを適用しない。
- 単日は単日テンプレート、期間は期間テンプレートで描画する。期間の `{Y2}` は元の名前に終了年がある場合だけ出力し、年を省略した形式でも空文字にする。
- 年月は2グループを年・月として解析し、年月テンプレートで描画する。標準年月パターンは年月の期間表記（`-`・`〜`・`～` で空白なく接続）の両端を除外する。年月ルールに限り、拡張子が `\.[0-9]{1,2}` に完全一致するファイルは対象外とする。
- どのパターンも一度もマッチしなかったファイルは、従来どおり変更対象外として結果から除外する。
- 全パターン適用後、連続空白を 1 つに畳み、前後の空白を除去する（`re.sub(r"\s{2,}", " ", stem).strip()`）。各パターン適用の都度ではなく、最終結果に対して1回のみ行う。
- 置換後の stem が元と同一のファイルは、変更対象外として結果リストに含めない。

**衝突回避**

- 親ディレクトリごとに「予約済み名」の集合を保持する。初期値はそのディレクトリの実在エントリ（リネーム元自身は除く）とし、確定した変更後名を順次追加する。
- 候補名が予約済みの場合、`_1`, `_2` … と連番サフィックスを付与して空きを探す。この仕組みにより、**既存ファイルとの衝突**と**同一バッチ内での衝突**を同一ロジックで解決する。
- 連番を付与した項目は `RESOLVED_CONFLICT` として記録し、プレビューで判別できるようにする。
- 大文字小文字を区別しないファイルシステムを考慮し、予約済み名の比較は `casefold()` で行う。

#### **B. リネーム実行 (RenameService)**

- `INVALID_DATE` の項目はスキップする。
- リネームには `Path.rename()` を使用する。`os.replace()` は既存ファイルを黙って上書きするため**使用しない**。
- 例外処理:
  - `FileExistsError`（走査後に第三者がファイルを作成した場合など）→ `SKIPPED` として記録し継続
  - `PermissionError` / その他の `OSError`（他アプリで開かれている、パス長超過など）→ `ERROR` として記録し継続
- 成功した項目のみを `ExecutionHistory` に格納し、`UndoService` のスタックに積む。

#### **C. Undo ロジック (UndoService)**

- **履歴スタック構造**: 実行された一括リネーム操作（`ExecutionHistory`）をメモリ上のスタック（LIFO）構造で管理する。アプリ終了時に履歴は破棄される（永続化しない）。
- **取り消し処理**:
  1. 履歴スタックから最新のセッションを取得。
  2. 競合を防ぐため、**実行時とは逆順**（末尾から）にファイル名を元の original_path へ復元。
  3. 復元完了後、履歴スタックから該当セッションを削除。
  4. Undo の実行自体もログファイルに記録。
- **欠損・競合時の扱い**: 復元元のファイルが存在しない、または復元先に既にファイルが存在する場合はその項目を `SKIPPED` とし、他のファイルの復元を継続する。

#### **D. ログ出力 (LogService)**

第 8 章「ログ設計」を参照。

#### **E. パターン・出力テンプレートプリセット管理 (PatternService / OutputTemplateService)**

**PatternService（複数選択用パターンプリセット）**

- 起動時に `%APPDATA%\rename-date\config\patterns.json` を読み込む。存在しない・パース失敗・スキーマ不正の場合は既定プリセット 1 件（名前「既定 (YYYY.M.D)」、パターン `\((\d{4})\.(\d{1,2})\.(\d{1,2})\)`）のみを持つファイルを新規生成する。
- 保存時は一時ファイルに書き込んだ後 `os.replace()` でアトミックに置き換える（リネーム対象ファイルの操作とは無関係の内部処理）。
- 各プリセットは保存前に ScannerService と同じ検証（正規表現コンパイル可否・キャプチャグループ数2〜6）を行い、不正なら保存を拒否してエラー表示する。
- プリセットは最低 1 件を維持する（全削除不可）。

**OutputTemplateService（単一選択用出力テンプレートプリセット）**

- 起動時に `%APPDATA%\rename-date\config\output_templates.json` を読み込む。存在しない・パース失敗・スキーマ不正の場合は既定プリセット 1 件（名前「既定 (YYYYMMDD)」、出力テンプレート `{Y}{M}{D}`）のみを持つファイルを新規生成する。
- 保存時は一時ファイルに書き込んだ後 `os.replace()` でアトミックに置き換える。
- 各プリセットは保存前に出力テンプレートの検証（プレースホルダ`{Y}{M}{D}`各1回以上・Windows禁止文字不使用）を行い、不正なら保存を拒否してエラー表示する。
- プリセットは最低 1 件を維持する（全削除不可）。

**RangeOutputTemplateService（期間用出力テンプレートプリセット）**

- 起動時に `%APPDATA%\rename-date\config\range_output_templates.json` を読み込む。存在しない・パース失敗・スキーマ不正の場合は既定プリセット1件（名前「既定 YYYYMMDD-[YYYY]MMDD」、テンプレート `{Y}{M}{D}-{Y2}{M2}{D2}`）を生成する。
- 保存時は一時ファイルに書き込んだ後 `os.replace()`でアトミックに置き換える。
- 保存前に `{Y}` `{M}` `{D}` `{Y2}` `{M2}` `{D2}` の全プレースホルダーとWindows禁止文字を検証し、不正なら保存を拒否する。
- プリセットは最低1件を維持し、名前重複は禁止する。

**MonthOutputTemplateService（年月用出力テンプレートプリセット）**

- 起動時に `%APPDATA%\rename-date\config\month_output_templates.json` を読み込む。存在しない・パース失敗・スキーマ不正の場合は既定プリセット1件（名前「既定 YYYY-MM」、テンプレート `{Y}-{M}`）を生成する。
- 保存時は既存サービスと同じ原子的な書き込みを使う。
- `{Y}` と `{M}` を各1回以上含み、対応しないプレースホルダー・波括弧・Windows禁止文字・U+0000〜U+001Fを含まないことを検証する。
- プリセットは最低1件を維持し、名前重複は禁止する。

#### **F. プリセットJSONの保存・取込**

- 入力パターン、年月・単日・期間出力テンプレートをそれぞれ個別に保存・取り込む。保存対象は選択中の項目に限らず、指定した種類の全件とする。
- JSONは内部設定と同じ配列形式で、入力パターンは `name` と `pattern`、テンプレートは `name` と `template` の文字列フィールドを持つ。配列は空にできない。保存はUTF-8（BOMなし）、取込はUTF-8 BOMの有無を許容する。
- 既定の保存ファイル名は `patterns.json`、`month_output_templates.json`、`output_templates.json`、`range_output_templates.json`。保存・取込先は稼働中の `base_dir` にある内部設定4ファイルを指定できない。他環境からコピーされた同形式のJSONは取り込める。
- 取込は追加のみとし、既存項目の後ろにファイル内の順序で追加する。JSON内または既存一覧と名前が完全一致（大文字小文字を区別）する項目があれば、重複項目名を示して全件を拒否する。項目名の異なる別種類間の重複は許可する。
- 既存のパターン・テンプレート検証を適用し、対象種類と一致しない形式、空配列、不正JSON、項目形式の不一致、検証エラー、読込・書込エラーを拒否する。エラー通知には可能な範囲でファイル名、項目名、配列位置、理由を含める。
- 取込元は読み取り専用とする。入力全件と追加後の一覧を検証してから、内部設定を一度だけ更新する。失敗・キャンセル時は取込元、内部設定、一覧、プレビューを変更しない。
- 保存先の内部設定ファイルを拒否した後、外部の既存ファイルにはアプリ側で上書き確認を行う。確認後、保存先と同じディレクトリの一時ファイルを経由して書き出し、取消・書込失敗でも既存ファイルを壊さない。
- 走査・一括変換・Undo中は取込を開始しない。取込成功後は対象一覧だけを更新し、選択状態を名前で維持（未選択も維持）する。古いプレビューと実行候補、再スキャン条件を破棄して再プレビューを案内する。Undo履歴は保持する。JSON保存では選択・プレビューを変更しない。

### **RenameItem**

```python
from dataclasses import dataclass
from enum import StrEnum
from pathlib import Path


class ItemStatus(StrEnum):
    PENDING = "PENDING"                      # 実行待ち
    INVALID_DATE = "INVALID_DATE"            # 日付として不正（実行対象外）
    RESOLVED_CONFLICT = "RESOLVED_CONFLICT"  # 連番付与で衝突を回避（実行対象）
    SUCCESS = "SUCCESS"                      # 成功
    SKIPPED = "SKIPPED"                      # スキップ
    ERROR = "ERROR"                          # エラー


@dataclass
class RenameItem:
    original_path: Path
    target_path: Path
    status: ItemStatus = ItemStatus.PENDING
    message: str = ""

    @property
    def original_name(self) -> str:
        return self.original_path.name

    @property
    def target_name(self) -> str:
        return self.target_path.name

    @property
    def parent_dir(self) -> Path:
        return self.original_path.parent

    @property
    def is_executable(self) -> bool:
        return self.status in (ItemStatus.PENDING, ItemStatus.RESOLVED_CONFLICT)
```

## **7\. 例外処理・安全対策方針**

1. **同名ファイルの競合**: 変更後の名前が既存ファイルまたは同一バッチ内の他の変更後名と衝突する場合、`_1`, `_2` … の連番サフィックスを付与して自動回避する（プレビュー段階で解決済みの名前を表示する）。
2. **走査後に発生した競合**: プレビュー後・実行前に第三者がファイルを作成した場合、`Path.rename()` が `FileExistsError` を送出するため SKIP として記録し処理を継続する。既存ファイルの上書きは行わない。
3. **不正な日付**: `(2024.13.45)` のようにパターンには一致するが日付として成立しない場合、プレビューに「無効」として表示し実行対象から除外する。
4. **権限エラー (PermissionError)**: ファイルが他アプリで開かれている等の理由でリネーム失敗時、エラーログを記録して処理を継続。
5. **パス長の超過**: 連番付与等により Windows のパス長上限を超えた場合、`OSError` を捕捉して ERROR として記録し継続する。
6. **不正な正規表現**: コンパイル不能、またはキャプチャグループ数が2〜6以外の場合、走査を実行せずエラーダイアログで通知する。
7. **Undo時の欠損対策**: Undo 実行時、リネーム後のファイルが手動で削除・移動されていた場合、または復元先に既にファイルが存在する場合はスキップし、他のファイルの復元を継続。
8. **UI のフリーズ回避**: 走査・実行・Undo はワーカースレッドで行い、UI 更新は `widget.after(0, ...)` を経由してメインスレッドで実施する。処理中は操作ボタンを無効化する。
9. **ReDoS への配慮**: ユーザーが入力した正規表現によっては走査が終わらない可能性があるため、キャンセルボタンを常に提供する。
10. **ログ出力の失敗**: ログ出力に失敗してもリネーム処理本体は中断しない（`logging` はハンドラ内の例外を呼び出し元に送出しない）。GUI 上はステータス表示に留める。
11. **パターン・出力テンプレートプリセットの不正**: 保存時の検証（正規表現／年月・単日・期間テンプレート）に失敗した場合は保存を拒否しエラーダイアログで通知する。`patterns.json` / `month_output_templates.json` / `output_templates.json` / `range_output_templates.json` が壊れている場合はそれぞれ既定プリセットにフォールバックする。
12. **ドロップ対象の欠損**: ドラッグ&ドロップされたパスが実在しない（ドラッグ中に削除された等）場合は対象から除外し警告表示する。
13. **プリセットJSON入出力の失敗**: 不正JSON・形式不一致・検証失敗・名前重複・I/Oエラーは既定値へ置き換えず、ファイルと可能なら項目名・位置・理由を示して通知する。取込時は既存一覧との重複を含めて全件を拒否し、内部設定は検証完了後に一度だけ更新する。内部設定4ファイルへの直接入出力は拒否し、外部保存では上書き確認の取消や書込失敗時に既存ファイルを保持する。失敗・キャンセル時は一覧とプレビューを変更しない。

## **8\. ログ設計**

### **8.1 出力先**

| 項目               | 内容                                                                             |
| ------------------ | -------------------------------------------------------------------------------- |
| 出力先ディレクトリ | `%APPDATA%\rename-date\logs\`                                                    |
| ファイル名         | `rename_log.txt`                                                                 |
| エンコーディング   | UTF-8（既定の cp932 では日本語ファイル名で `UnicodeEncodeError` となるため必須） |
| 出力タイミング     | 一括実行 / Undo の完了時に追記（ログ保存チェックボックスが ON の場合）           |

### **8.2 ログ書式**

1 行 1 項目のタブ区切り (TSV) とする。

```text
<ISO8601 日時>\t<session_id>\t<action>\t<status>\t<変更前パス>\t<変更後パス>\t<メッセージ>
```

- `action`: `RENAME` または `UNDO`
- `status`: `SUCCESS` / `SKIPPED` / `ERROR` / `INVALID_DATE` / `RESOLVED_CONFLICT`
- ファイル名に含まれるタブ・改行はエスケープしてから書き込み、ログの行構造が壊れることを防ぐ。

### **8.3 ローテーション方針**

標準ライブラリの `logging.handlers.RotatingFileHandler` による**サイズベース**のローテーションを採用する。断続的にしか起動しないデスクトップアプリでは、時刻ベース (`TimedRotatingFileHandler`) よりも「ディスク使用量に上限を設ける」というサイズベースの目的が要件に合致するため。

| 設定          | 値      | 意図                                                           |
| ------------- | ------- | -------------------------------------------------------------- |
| `maxBytes`    | 1 MiB   | 1 行あたり 150〜300 バイト程度のため、およそ 4,000〜7,000 件分 |
| `backupCount` | 5       | 世代を含めた最大サイズを **6 MiB** に固定                      |
| `encoding`    | `utf-8` | 日本語ファイル名への対応                                       |
| `delay`       | `True`  | ログ保存を使用しない場合に空ファイルを作らない                 |

- 世代ファイル名は `rename_log.1.txt` … `rename_log.5.txt` とする（`handler.namer` を差し替え、拡張子を末尾に保つことで関連付けから開けるようにする）。
- ロールオーバーはレコード単位で行われるため、1 行が複数ファイルに分断されることはない。ただし 1 回の一括実行が 2 ファイルにまたがる可能性はあるため、全行に `session_id` を付与して再構成可能にする。
- 名前付きロガー (`rename_date.audit`) を使用し、`propagate = False` としてルートロガーへの二重出力を防ぐ。ハンドラの二重登録も防止する。
- アプリ終了時に `logging.shutdown()` を呼び、ファイルハンドルを確実に解放する。
- アンインストール時にもログディレクトリは削除しない。

## **9\. 多重起動抑止**

Undo 履歴をプロセス内メモリで保持する設計であるため、複数インスタンスが同時に同じフォルダを操作すると履歴の整合性が失われる。また、複数プロセスが同じログファイルのハンドルを保持するとローテーション時のリネームが失敗する。これらを避けるため多重起動を抑止する。

### **9.1 方式**

- 起動時に名前付きミューテックス（`ctypes` 経由の `CreateMutexW`）を取得する。`GetLastError()` が `ERROR_ALREADY_EXISTS` の場合は既に起動中と判断する。
- ミューテックス名はユーザーセッション内で一意になる固定文字列（例: `Local\rename-date-single-instance`）とする。
- 実装は `src/rename_date/single_instance.py` に隔離し、コンテキストマネージャとして提供する。

### **9.2 二重起動時の挙動**

1. 既存ウィンドウを検索して前面に表示する（`FindWindowW` + `SetForegroundWindow`）。
2. 新しいプロセスはメッセージを表示せずに終了する。
3. 既存ウィンドウの検出に失敗した場合のみ、「既に起動しています」というメッセージボックスを表示して終了する。

### **9.3 異常終了時の考慮**

名前付きミューテックスはプロセス終了時に OS が自動的に解放するため、アプリがクラッシュしてもロックが残留しない。ロックファイル方式に対する明確な利点であり、本方式を採用する理由の 1 つである。

## **12\. スコープ外 / 将来の拡張候補**

本バージョンでは以下を実装しない。

- プレビュー画面でのチェックボックスによる対象の個別選択
- Redo（Undo の取り消し）
- フォルダ名のリネーム
- Undo 履歴の永続化（アプリ終了時に破棄する）
- 正規表現以外の変換ルール（連番付与、大文字小文字変換など）
- 除外パターンの GUI 上での編集（`config.py` の定数で管理する）
- フォルダ選択履歴の永続化（前回使用フォルダの記憶。正規表現/出力テンプレートのプリセットは本要件で対象内となった）
- 多言語対応（UI は日本語のみ）
