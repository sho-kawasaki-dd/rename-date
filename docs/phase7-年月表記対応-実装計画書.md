# Phase 7: 年月表記対応 実装計画書（v0.4.0）

対象: [rename-date開発計画書.md](./rename-date開発計画書.md) の変換・プリセット仕様。[Phase 5](./phase5-期間表記対応-実装計画書.md) のパターン種別判定と [Phase 6](./phase6-プリセットJSON保存・取込-実装計画書.md) のプリセット入出力を拡張する。

## 目的

`売上_2026.7.pdf` を `売上_2026-07.pdf` に変換できるようにする。年月を単日・期間とは別の種別として扱い、既存の変換結果や設定を維持したまま、同じプレビューで併用できるようにする。この改修を含むアプリとインストーラーのバージョンを `v0.4.0` とする。

## 要件

### A. 入力パターンと変換

- 正規表現のキャプチャグループ数で判定する。**2グループは年月（年、月）**とし、3は単日、4〜6は期間のまま変更しない。コンパイル失敗または2〜6以外のグループ数は `InvalidPatternError` とし、保存・取込・走査を拒否する。
- 入力パターン一覧は共用し、年月の項目に `[年月]` を表示する。`patterns.json` は引き続き `name` と `pattern` の配列を使う。既存・新規の設定に年月パターンは自動追加せず、利用者が新規作成または取込し、選択した場合に適用する。
- 標準の入力例は `(?<![0-9])(?<!(?<![0-9])[0-9]{4}\.[0-9][-〜～])(?<!(?<![0-9])[0-9]{4}\.[0-9]{2}[-〜～])([0-9]{4})\.([0-9]{1,2})(?![0-9]|[.-][0-9]|[〜～][0-9]{4}\.[0-9]{1,2}(?![0-9]))` とする。`YYYY.M`・`YYYY.MM` にマッチし、`2026.11.26.pdf`・`2026.11-26.pdf` は部分変換しない。2つの年月が `-`・`〜`・`～` のいずれかで空白なしにつながる場合は、両端とも変換しない。同じファイル名に独立した年月があれば、その箇所は変換する。この期間除外は標準パターンの境界条件であり、独自パターンに一律適用しない。独自パターンでは対象の表記に合わせて境界を指定し、プレビューで確認する。
- 適用順は **期間 → 単日 → 年月**。同種内は一覧順を維持し、先行ルールの出力に後続ルールを適用する既存の逐次置換を維持する。各パターンのすべてのマッチを置換し、空白の正規化・変更なしの非表示・名前衝突の回避は既存処理を使う。
- 年は1〜9999、月は1〜12を有効とし、年は4桁、月は2桁にゼロ埋めする。非数値や必須グループの欠落も不正とする。1箇所でも不正な年月にマッチしたファイルは `ItemStatus.INVALID_DATE` としてプレビューに残し、部分的に変換して実行しない。
- 書き換えるのは `Path.stem` のみとし、拡張子を変更しない。`2026.11` 単独は stem が `2026` になるため対象外。`2026.11.26` は stem が `2026.11` になるため、**拡張子がドットに続く1〜2桁の半角数字だけなら、年月ルールを適用しない**。この除外は年月ルールに限り、単日・期間には影響させない。

### B. 年月出力テンプレートとJSON入出力

- 既定プリセット名は `既定 YYYY-MM`、既定テンプレートは `{Y}-{M}` とする。`{Y}` と `{M}` を各1回以上含め、他のプレースホルダー・対応しない波括弧（ネストした波括弧を含む）・Windowsのファイル名禁止文字（`U+0000`〜`U+001F` の制御文字を含む）は拒否する。単日・期間のテンプレート検証は変更しない。
- `%APPDATA%\rename-date\config\month_output_templates.json` に `name` と `template` の配列として別保存する。ファイルがない場合は既定1件を作成する。既存の内部設定3ファイルを移行・書き換えしない。
- メイン画面に年月用テンプレートの選択・追加・編集・削除を追加し、最後の1件は削除できないようにする。年月パターンの選択時だけ年月用テンプレートの選択を必須にし、未選択なら警告して走査しない。年月パターン未選択かつ年月用テンプレート未選択時は既定テンプレート `{Y}-{M}` を補って走査し、既存の単日・期間の選択条件は変えない。選択パターンに不正なものが含まれる場合は、年月用テンプレートの未選択警告より従来の走査エラー通知を優先し、直前のプレビュー結果を実行できないようにする。
- 「プリセット」メニューに「年月出力テンプレート」を追加し、Phase 6 と同様に全件を書き出し、取込は追加のみとする。同名や不正項目が1件でもあれば全件を拒否する。内部設定4ファイルへの直接入出力を禁止し、取込成功時は対象一覧の選択とUndo履歴を維持しつつ、古いプレビューを破棄して再プレビューを案内する。
- **旧版との設定共用は対象外。** 2グループの項目を含む `patterns.json` を v0.3.0 が読み込むと、入力パターン一覧全体が既定値で上書きされる。更新前に設定をバックアップし、旧版に戻す場合は旧版の初回起動前に、年月項目を含まない更新前の `patterns.json` を復元する手順を [取扱説明書](../取扱説明書.md) に明記し、v0.4.0 リリースノート作成時はその記載を参照する。

## タスク

### 1. Services：種別判定・変換・テンプレート管理

- [x] [validation.py](../src/rename_date/services/validation.py) に `PatternKind.MONTH` と `validate_month_output_template` を追加する。キャプチャグループ数の対応表を検証と判定で共用し、グループ数エラー文言を `"pattern must contain 2 (month), 3 (single), or 4 to 6 (range) capture groups"` に更新する。年月テンプレート検証は `{Y}`・`{M}` の存在確認後、単一パス置換（`re.sub(r"\{(?:Y|M)\}", "", template)`）の残余に `{` / `}` がないことを確認する。既存の Windows 禁止文字に加え、`U+0000`〜`U+001F` が含まれていれば `InvalidTemplateError` を送出する。保存・JSON取込・走査では同じ年月用検証を使う。
- [x] [date_span.py](../src/rename_date/services/date_span.py) に `YearMonth(year: int, month: int)` と `parse_month_match` / `render_month` を追加する。整数変換は既存の `_to_int` を再利用し、`date(year, month, 1)` で年・月の有効範囲を検証して日は保持・描画しない。既存の `parse_match` は `PatternKind.RANGE` を明示判定し、`PatternKind.MONTH` を渡された場合は `ValueError` を送出する。
- [x] [ScannerService](../src/rename_date/services/scanner_service.py) に既定値付きのキーワード専用引数 `month_output_template: str = config.DEFAULT_MONTH_OUTPUT_TEMPLATE` を追加する。既存の位置引数を維持し、走査前に年月用テンプレートを検証する。種類の優先順位（期間 → 単日 → 年月）で安定ソートし、年月用の解析・描画と、`re.fullmatch(r"\.[0-9]{1,2}", source.suffix)` による ASCII 半角1〜2桁数字拡張子の除外（`PatternKind.MONTH` のみスキップ）を組み込む。
- [x] [config.py](../src/rename_date/config.py) に `DEFAULT_MONTH_TEMPLATE_NAME = "既定 YYYY-MM"`、`DEFAULT_MONTH_OUTPUT_TEMPLATE = "{Y}-{M}"`、`MONTH_OUTPUT_TEMPLATES_FILE_NAME = "month_output_templates.json"` を追加し、`PRESET_FILE_NAMES` に含める。[OutputTemplateService](../src/rename_date/services/output_template_service.py) の既存サブクラス方式で `MonthOutputTemplateService` を追加し、内部保存・厳密な外部JSON検証・原子的な書き込みを再利用する。

### 2. Views・Controller：設定とプレビュー

- [x] [起動処理](../src/rename_date/__main__.py) で `MonthOutputTemplateService` を生成し、[AppController](../src/rename_date/controllers/app_controller.py) に渡す。[ConfigFrame](../src/rename_date/views/config_frame.py) の出力テンプレート欄を単日・期間・年月の各2段構成（上段に種別ラベルと右寄せ操作ボタン、下段に全幅コンボボックス）へ見直し、年月用の選択・追加・編集・削除を追加する。[出力テンプレート編集ダイアログ](../src/rename_date/views/output_template_dialog.py) に年月用検証とタイトル・説明文（`年月用テンプレートプリセット`、`{Y}{M}` のみ利用可）を渡す。パターン一覧に `[年月]` を表示し、[パターン編集ダイアログ](../src/rename_date/views/pattern_dialog.py) のグループ数案内を更新する。
- [x] [MainWindow](../src/rename_date/views/main_window.py) のプリセットメニューと保存・取込ダイアログに年月用を追加し、Controllerの種類別処理につなぐ。取込時は明示的な種別分岐と未知種別の `ValueError` を使い、選択復元、処理中の取込拒否、上書き確認、エラー通知、プレビュー無効化を既存の方式で行う。
- [x] `_on_preview_request` で既存の必須選択を確認した後、全選択パターンの種別を検証して年月テンプレートの必須選択を判定する。不正パターンがある場合は年月テンプレート未選択の警告を優先せず、既定年月テンプレートを補って `_start_scan` から走査ワーカーへ渡す。年月パターンがない場合の未選択も既定値で補う。走査条件には年月テンプレートを保存し、実行・Undo後の再走査で元の条件を使う。

## スコープ外

- `2026.11` 単独のように年月が拡張子と区別できない名前の変換や、拡張子の判定ルールの変更。
- 年月の期間を一つの範囲として解析・変換する機能、年だけの変換、単日・期間テンプレートの仕様変更。
- 新旧バージョン間の設定共用、設定の自動移行、Gitタグ作成、GitHub Releaseへの公開。
