# Phase 8: 高DPI対応 実装計画書（v0.4.1）

対象: [起動処理](../src/rename_date/__main__.py)、[メイン画面](../src/rename_date/views/main_window.py)、[配布設定](../installer/rename-date.spec)。

## 目的

Windowsの高解像度ディスプレイや拡大表示環境で、OSによるビットマップ拡大に起因するUIのぼやけを改善する。既存の操作・設定を維持し、この改修を含むアプリとインストーラーのバージョンを `v0.4.1` とする。

## 要件

- DPI対応は**システムDPI対応**を基本とする。起動時のシステムDPIに合わせて描画し、DPI非対応プロセスとしてWindowsに引き伸ばされないこと。100%・150%・200%の表示倍率で文字や操作部品が判読でき、主要な操作が可能であること。
- DPI設定は最初のTkウィンドウ生成前に行う。通常の起動経路と、二重起動時に既存ウィンドウを有効化できずダイアログを表示する経路の両方を対象にする。既にシステムDPI以上の対応が設定されている場合はその状態を維持し、設定失敗時は現在のDPI対応状態を確認して、非対応のままであればエラーを明示する。
- `uv run main.py` とPyInstaller製のexeの両方で対応する。exeのマニフェストと起動時の処理が矛盾しないことを確認し、`tkinterdnd2` の同梱とドラッグ&ドロップを維持する。DPI設定を行うための新たな依存は追加しない。
- Tkが取得するDPIと既存のレイアウトを基本とし、根拠のない固定倍率や二重スケーリングを加えない。高倍率で切れる箇所が確認された場合は、既存の画面操作を維持する範囲で修正する。
- システムDPI対応では、異なる倍率のモニターへの移動や起動後の表示倍率変更に追従しない場合があり、Windowsによる拡大でぼやけることがある。対象モニターをメインディスプレイに設定してサインアウト・サインイン後にアプリを起動する回避方法を案内する。モニターごとの動的DPI対応は本計画の対象外とする。
- 既存の変換処理、プリセット、ログ、Undo、多重起動抑止、インストーラーの `AppId` を変更しない。

## タスク

### 1. DPI初期化とレイアウト

- [x] [起動処理](../src/rename_date/__main__.py) の最初のTkウィンドウ生成より前に、Windowsの `SetProcessDpiAwarenessContext` でシステムDPI対応を指定する処理を追加する。APIの引数・戻り値の型と失敗時のエラー取得を明示し、二重起動時のダイアログも含むすべての起動経路で実行されるようにする。
- [x] 設定前後のプロセスのDPI対応状態をWindows APIで確認する。既存のマニフェスト等により設定済みでAPIが変更を拒否した場合も、実際にシステムDPI対応またはそれ以上であれば続行する。非対応のままの場合や状態を確認できない場合は、原因を含むエラーを明示して終了し、成功扱いにしない。
- [ ] [PyInstaller設定](../installer/rename-date.spec) でexeにシステムDPI対応を宣言するマニフェストを指定する。生成されたexeの実際のマニフェストと実行時DPI対応状態を確認し、起動時処理と競合しないことを検証する。ソース起動時も同じ初期化処理で対応する。
- [ ] [メイン画面](../src/rename_date/views/main_window.py) と各設定ダイアログを高倍率で確認し、文字・ボタン・表・メニューが切れて操作不能になる箇所があれば、必要最小限のレイアウト修正を行う。固定ウィンドウ寸法や最小サイズを変更する場合は、実際の表示領域に収まり操作できることも確認する。

### 2. テストとWindows実機検証

- [x] DPI初期化の自動テストを追加し、未設定時の設定成功、設定済みで変更が拒否された場合の続行、非対応のままの失敗、状態取得失敗を確認する。Tkの生成より前に初期化する順序と二重起動時のダイアログ経路も検証する。Windows APIの呼び出しを代替して判定をテストし、実際のDPI状態は別途実機で確認する。
- [x] 対象テストを実行し、`uv run pytest --cov=src/rename_date --cov-report=term-missing` で既存の回帰とServices層カバレッジ85%以上を確認する。
- [ ] Windowsの検証環境で、各倍率を適用したセッションでアプリを起動し、100%・150%・200%それぞれについて、ソース起動と配布exeの実行時DPI対応状態をWindows APIで確認する。OSによるDPI非対応アプリのビットマップ拡大がないことと、文字・ボタンのぼやけや欠けがないことを目視確認する。表示解像度・倍率・確認結果を記録する。
- [ ] 各倍率でメイン画面、ログ、入力パターン・出力テンプレート編集、ファイル選択ダイアログ、最小サイズ時の操作を確認する。プレビュー・実行・Undo、ファイルとフォルダーのドラッグ&ドロップ、二重起動時の既存ウィンドウ有効化と通知も確認する。
- [ ] 倍率の異なるモニター間の移動と表示倍率変更後の挙動を確認し、システムDPI対応の制約を超える動的追従を合格条件にしない。確認できない環境がある場合は未検証として残す。

### 3. ドキュメント・バージョン・インストーラー

- [x] [取扱説明書](../取扱説明書.md) に高DPI対応の内容、異なる倍率のモニター間移動時や倍率変更後の制約・回避方法を追記する。[開発計画書](./rename-date開発計画書.md) に本Phaseを追加する。
- [x] `uv version 0.4.1` で [pyproject.toml](../pyproject.toml) と [uv.lock](../uv.lock) を更新し、[setup.iss](../installer/setup.iss) の単独ビルド時の既定値も `0.4.1` に揃える。`uv lock --check` と `uv run --locked python -c "from importlib.metadata import version; assert version('rename-date') == '0.4.1'"` で確認する。既存の `AppId` は維持する。
- [x] Inno Setupの `iscc.exe` を使用できるWindowsの**検証用作業コピー**で `pwsh -File .\scripts\build-release.ps1`（PowerShell 7がない場合は `powershell -File .\scripts\build-release.ps1`）を実行し、`installer\Output\rename-date-0.4.1-setup.exe` の生成を確認する。このスクリプトは `build`・`dist`・`installer\Output` を削除するため、既存の成果物を消さない環境で実行する。
- [ ] 検証用プロファイルでv0.4.0から上書きインストールし、インストール済みバージョンが `0.4.1` であること、既存のプリセットとログが保持されること、インストール後のexeでもDPI対応とプレビュー・実行・Undo・ドラッグ&ドロップが動作することを確認する。インストール前後の設定ファイルを比較し、意図しない変更がないことを確認する。
