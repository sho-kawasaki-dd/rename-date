# Phase 5: 期間表記（YYYY.MM.DD-MM.DD）対応 実装計画書

対象: [rename-date開発計画書.md](./rename-date開発計画書.md) の第1.2〜1.3章・第3.1章・第4.1章・第4.2.A章・第4.2.E章・第5章・第6章・第7章・第11章、[.github/copilot-instructions.md](../.github/copilot-instructions.md) の「変更してはいけない契約」、[パターン設定ガイド.md](../パターン設定ガイド.md)、[取扱説明書.md](../取扱説明書.md)。Phase 1.5〜Phase 3 で完成済みの `validation` / `ScannerService` / `OutputTemplateService` / `ConfigFrame` / `AppController` を拡張する。

## 目的

現行仕様は「正規表現は年・月・日の3キャプチャグループ固定」であり、`写真 (2024.12.20-12.25).jpg` のように期間で書かれた日付を変換できない。本フェーズでは、既存の単日変換の挙動と保存データ（`patterns.json` / `output_templates.json`）を壊さずに、期間表記を `YYYYMMDD-MMDD` / `YYYYMMDD-YYYYMMDD` 形式へ変換できるようにする。

## 要件

### A. パターンの種類判定（キャプチャグループ数による自動判定）

- `PatternEntry` / `patterns.json` のスキーマは変更しない（`name` + `pattern` のまま。移行処理は不要）。
- キャプチャグループ数で種類を判定する。3・4・5・6 以外はこれまでどおり `InvalidPatternError` とする。

  | グループ数 | 種類 | グループの意味（左から順） |
  |---|---|---|
  | 3 | 単日 (`SINGLE`) | Y, M, D |
  | 4 | 期間 (`RANGE`) | Y, M, D, D2 |
  | 5 | 期間 (`RANGE`) | Y, M, D, M2, D2 |
  | 6 | 期間 (`RANGE`) | Y, M, D, Y2, M2, D2 |

- Y・M・D・D2 は必須。Y2・M2 は省略可能なグループ（`(...)?`）にしてよく、マッチしなかった場合は `None` として扱う。これにより、次の1つのパターンで3つの入力形式すべてに対応できる。

  ```text
  \((\d{4})\.(\d{1,2})\.(\d{1,2})-(?:(?:(\d{4})\.)?(\d{1,2})\.)?(\d{1,2})\)
  ```

### B. 期間の解釈と日付の妥当性

- 開始日は `date(Y, M, D)` で作る。`ValueError` なら `INVALID_DATE` とする。
- 終了日は省略された単位を開始日から補って作る。
  - Y2・M2 がどちらも無い場合: `(Y, M, D2)`。終了日が開始日より前なら、月を1つ進める（12月なら翌年1月）。例: `2024.12.30-02` → 2025-01-02。
  - Y2 が無く M2 がある場合: `(Y, M2, D2)`。終了日が開始日より前なら、年を1つ進める。例: `2024.12.25-01.05` → 2025-01-05。
  - Y2 がある場合: `(Y2, M2, D2)`。終了日が開始日より前なら `INVALID_DATE` とする（繰り上げない）。
  - Y2 があるのに M2 が無いという矛盾した一致は `INVALID_DATE` とする。
- 繰り上げた後の日付が存在しない場合（例: `2024.01.31-30` → 2月30日）は `INVALID_DATE` とする。
- 開始日と終了日が同じ日の場合は有効とする。
- 1つでも `INVALID_DATE` になる一致があれば、これまでどおりそのファイル全体を `INVALID_DATE` とし、それ以降のパターンは適用しない。

### C. 出力テンプレート

- 期間用の出力テンプレートを単日用とは別のプリセットとして用意し、`%APPDATA%\rename-date\config\range_output_templates.json` に保存する。既存の `output_templates.json` は変更しない。
- 期間用テンプレートのモデルは既存の `OutputTemplateEntry`（`name` + `template`）を使う。
- 既定値: 名前 `既定 YYYYMMDD-[YYYY]MMDD`、テンプレート `{Y}{M}{D}-{Y2}{M2}{D2}`。
- 変換時のルール:
  - `{Y}` は4桁、`{M}` `{D}` `{M2}` `{D2}` は2桁ゼロ埋め。
  - `{Y2}` は、元の名前に終了側の年が書かれていた場合だけ4桁で出力し、書かれていなければ空文字にする（年をまたいだ場合でも、元に年が無ければ空文字）。
  - 終了側が日だけの形式（4グループ、または M2 省略）でも `{M2}` は補った月で出力する。
- 変換例（既定テンプレート）:

  | 変換前 | 変換後 |
  |---|---|
  | `(2024.12.20-2025.01.05)` | `20241220-20250105` |
  | `(2024.12.20-12.25)` | `20241220-1225` |
  | `(2024.12.20-25)` | `20241220-1225` |
  | `(2024.12.25-01.05)` | `20241225-0105` |

- 保存時の検証:
  - 期間用テンプレートは `{Y}` `{M}` `{D}` `{Y2}` `{M2}` `{D2}` をすべて1回以上含むことを必須とする。
  - 単日用テンプレートで `{Y2}` `{M2}` `{D2}` を使うことは禁止する。
  - Windows のファイル名に使えない文字の禁止は、両方に適用する。

### D. 適用順

- 一覧で選択したパターンのうち、**期間パターンをすべて単日パターンより先に適用する**。期間同士・単日同士の中では、一覧の表示順を保つ（安定な並べ替え）。
  - 理由: 括弧なしの単日パターンを先に適用すると、`2024.12.20-2025.01.05` の開始日と終了日がそれぞれ単日として変換されてしまうため。
- それ以外のパイプライン方式（1つ前のパターンの結果に対して適用、空白整理は最後に1回、元と同じ名前なら除外、`_1`, `_2` … による衝突回避）は変更しない。

### E. GUI

- 出力テンプレート欄に、期間用テンプレートのコンボボックスと New / Edit / Delete ボタンを追加する。最後の1件は削除できない。
- パターン一覧の各行に種類（`[単日]` / `[期間]`）を表示する。
- パターン編集ダイアログでは、保存時の検証メッセージを「グループ数は3（単日）または4〜6（期間）」に更新する。

### F. 変えないこと

- 置換対象は `Path.stem` のみ、`Path.rename()` のみ使用、Undo・ログ・多重起動抑止は変更しない。
- Services 層は tkinter を import しない。Services 層のカバレッジ 85% 以上を維持する。

- 名前付きグループ（`(?P<Y>...)`）による指定。
- 3日以上の日付を並べた表記（例: `2024.12.20-25-30`）や、`〜` などの区切りを特別扱いすること（区切りは正規表現側で吸収する）。
- 終了日を開始日より前として許容する、日数を計算して出力するなどの期間の高度な処理。
- 開発計画書 第12章に記載のスコープ外事項（Redo、フォルダ名リネーム、Undo 履歴の永続化など）。
